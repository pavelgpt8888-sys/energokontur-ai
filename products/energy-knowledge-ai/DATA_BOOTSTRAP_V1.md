# Energy Knowledge AI BY — Data Bootstrap v1

## Цель

Собрать первую промышленно-пригодную базу Energy Knowledge AI BY из открытых и официально доступных источников энергетического сектора Республики Беларусь.

## Основной источник: ЭИС «Энергодокумент»

`https://energodoc.by/`

ЭИС создана по поручению ГПО «Белэнерго», содержит действующие НПА, ТНПА и иные документы по проектированию, строительству, монтажу, наладке, эксплуатации и ремонту энергетических объектов. Система указывает, что публично размещает электронные тексты документов, публикация которых разрешена законодательством; внутренние СТП и часть другой внутренней документации требуют регистрации.

На момент инвентаризации 2026-08-23 каталог `/document` показывает 3 486 записей. Раздел «Электроэнергетика» показывает 254 НПА и 2 852 ТНПА.

### Что собираем

Для каждой доступной карточки:

- source_id;
- energodoc_document_id;
- title;
- document_type;
- issuer;
- approval_date;
- approval_number;
- effective_date;
- status / edition note;
- category;
- topical rubric;
- distributor;
- source_url;
- public_fulltext_url, если полный текст действительно доступен без авторизации;
- fulltext_access: `public | registered | metadata_only | unknown`;
- discovered_at;
- last_seen_at;
- content_hash / metadata_hash;
- provenance.

### Правило прав на контент

Наличие карточки в каталоге НЕ означает право копировать полный текст. Полный текст забирается только если он опубликован в ЭИС без авторизации и его использование допускается условиями источника/законодательством. В остальных случаях сохраняем metadata + ссылку и используем документ как реестровую запись до получения законного доступа.

## Источник 2: официальный сайт Минэнерго

`https://minenergo.gov.by/law/`

Обязательные разделы для crawler:

1. Законы Республики Беларусь.
2. Указы Президента.
3. Директивы Президента.
4. Декреты Президента.
5. Постановления Совета Министров.
6. НПА Минэнерго и других госорганов.
7. ТНПА.
8. Концепции, программы и комплексные планы.
9. Проекты документов.

Этот источник используем как официальный источник ведомственной классификации и подтверждения номера/даты/органа/связей изменений.

## Источник 3: ОАО «Экономэнерго» / energystrategy.by

`https://energystrategy.by/normative-document`

Используем для:

- новых/переизданных ТНПА;
- признаков `ВЗАМЕН`, `ОТМЕНЕН`, `с учетом Изменения`;
- дат ввода в действие;
- описаний сферы действия;
- кросс-проверки с ЭИС «Энергодокумент» и Минэнерго.

## Источник 4: ЭТАЛОН-ONLINE / pravo.by

Используем как reference source для НПА и проверки актуальности правовых актов. Автоматический сбор должен учитывать условия доступа и не обходить ограничения сайта.

## Источник 5: Национальный фонд ТНПА / tnpa.by

Используем для идентификаторов и библиографических сведений о ТНПА, когда страницы Минэнерго ссылаются на фонд.

## Источник 6: ГПО «Белэнерго» и отраслевые организации

Публичные документы Белэнерго, Госэнергогазнадзора, БелАЭС и иных организаций подключаются как дополнительные approved sources после аудита.

## Порядок автоматического сбора

```text
scheduler
  -> source adapter
  -> list/discovery pages
  -> document cards
  -> normalize metadata
  -> detect public full text
  -> fetch allowed full text
  -> parse/OCR if needed
  -> document registry
  -> version/relation resolver
  -> indexing
  -> retrieval evaluation
```

## Trust policy

LLM может помогать извлекать metadata и предлагать связи, но не является источником истины.

Критичные поля (`active/replaced/expired`, effective date, replaces/replaced_by) подтверждаются:

1. официальной карточкой/актом;
2. вторым доверенным источником, если данные конфликтуют;
3. иначе статус `unknown` + human review.

## MVP dataset target

Первый полный bootstrap: все публично видимые карточки ЭИС «Энергодокумент» (~3.5k на 2026-08-23) + разделы законодательства Минэнерго.

Полный текст индексируем только для документов, которые легально и технически доступны без авторизации. Для остальных индексируем metadata и краткое официальное описание.

## Definition of Done

- crawler проходит все публичные страницы каталога;
- каждая запись имеет provenance;
- повторный запуск идемпотентен;
- изменения metadata фиксируются;
- новые документы обнаруживаются автоматически;
- доступные публичные тексты попадают в полнотекстовый/RAG индекс;
- restricted документы не копируются;
- document/version graph формируется из подтвержденных связей;
- есть ежедневный incremental sync;
- результаты проходят retrieval eval.
