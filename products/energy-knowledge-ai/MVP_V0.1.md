# MVP v0.1 — Energy Knowledge AI BY

## Goal

Собрать живой демонстрационный продукт, который можно показать на встрече в Минэнерго или ГПО «Белэнерго» без доступа к их внутренней инфраструктуре.

## Demo scope

Первая версия работает на легально доступной публичной энергетической нормативной базе.

### Обязательные пользовательские сценарии

1. **Спросить** — получить ответ только по подключённым источникам.
2. **Найти документ** — по номеру, названию, дате, органу или смыслу.
3. **Показать источник** — документ + раздел/страница/фрагмент.
4. **Какая редакция действует?** — показать active/superseded статус.
5. **Сравнить редакции** — кратко показать ключевые изменения.
6. **Нет ответа** — корректно отказаться при отсутствии доказательств.

## Demo UX

Минимальный интерфейс:

- строка «Спросите об энергетической нормативной базе»;
- кнопки: `Спросить`, `Найти документ`, `Сравнить редакции`, `Что изменилось`;
- карточки источников;
- переход к исходному документу/странице, если источник позволяет;
- заметная маркировка статуса документа.

## Initial corpus

Для убедительного демо достаточно примерно 300–1 000 хорошо подготовленных документов/записей. Приоритет качества и связей выше количества.

Категории:

- электроэнергетика;
- теплоснабжение;
- электробезопасность;
- охрана труда;
- техническая эксплуатация;
- постановления Минэнерго;
- ТКП и связанные документы, которые можно использовать законно;
- публичные справочные материалы.

Перед включением полного текста необходимо проверить право на его хранение/использование. Если распространение ограничено, хранить только допустимые метаданные/выдержки/ссылку либо использовать документ только при законном основании.

## Technical MVP

### Backend
- Python;
- FastAPI.

### Data
- PostgreSQL;
- pgvector или Qdrant для vector search;
- BM25/OpenSearch или иной полнотекстовый индекс;
- S3-compatible storage при необходимости хранения файлов.

### AI pipeline

```text
Document
↓
parser / OCR
↓
metadata extraction
↓
structural chunking
↓
keyword + vector indexing
↓
Document Registry

Question
↓
query normalization
↓
hybrid retrieval
↓
reranker
↓
validity/version filter
↓
context builder
↓
Qwen via Belarus provider
↓
citation validation
↓
answer
```

## Model requirement

Для v0.1 не нужна frontier-модель. Базовое требование — стабильная LLM у белорусского провайдера, достаточная для synthesis (сборки ответа) из хорошо найденного контекста. Предпочтительный первый кандидат — Qwen, если API/условия провайдера подходят.

## Evaluation set

До демонстрации создать 50 контрольных вопросов:

- 10 exact retrieval;
- 10 semantic retrieval;
- 10 questions about current revision;
- 10 comparison questions;
- 10 unanswerable questions.

Цели demo-quality:

- правильный источник в top results: ≥90%;
- citation accuracy: ≥95% на контрольной выборке;
- отсутствие выдуманного уверенного ответа при unanswerable запросах;
- стабильный переход к источнику.

## Non-goals v0.1

Не делать в первой версии:

- полноценную интеграцию с 1С;
- СЭД-коннекторы;
- сложный корпоративный ACL;
- autonomous agents;
- собственную LLM;
- собственный OCR engine;
- покупку GPU;
- миллион документов;
- GLM как обязательный runtime-компонент.

## Definition of Done

MVP v0.1 готов к показу, если человек без обучения может:

1. открыть web-интерфейс;
2. задать реальный вопрос;
3. получить краткий подтверждённый ответ;
4. открыть источник;
5. проверить актуальность редакции;
6. сравнить две версии;
7. увидеть честный отказ там, где информации нет.
