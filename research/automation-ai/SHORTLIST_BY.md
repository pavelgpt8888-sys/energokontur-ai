## Критерии

Каждый критерий от 1 до 5, максимум 25 баллов.

- **Спрос в РБ** — есть боль и платёжеспособный покупатель; идея не завязана на нормативку РФ.
- **Стек** — насколько собирается из того, что уже умеете.
- **Скорость** — MVP силами одного разработчика с ИИ-ассистентом для кода.
- **Продажи** — короткий цикл: решение принимает владелец или руководитель частной компании.
- **Госпуть** — дорога к облэнерго, ГПО «Белэнерго» и Минэнерго после частных кейсов.

## Карточки

### 1. Цифровая ЭТЛ
- **Что:** ввод замеров на объекте без связи → автоматическая проверка по нормам → протоколы и технический отчёт по формам лаборатории одной кнопкой; реестр приборов со сроками поверки; напоминания клиентам о повторных испытаниях.
- **Кто платит:** частные электролаборатории, лаборатории монтажных и наладочных организаций; позже — лаборатории облэнерго.
- **Адаптация к РБ:** нормы приёмо-сдаточных испытаний по ТКП 339, эксплуатационных — по ТКП 181; формы протоколов конкретной лаборатории.
- **MVP:** 4–6 недель. Ядро на Python + PostgreSQL + шаблоны DOCX; ввод через веб-приложение (PWA). ИИ — контроль протоколов на ошибки (идея 125).
- **Риски:** точность таблиц норм; у каждой лаборатории свои формы; есть российские программы для ЭТЛ.

### 2. Электрохозяйство под ключ
- **Что:** анкета по объекту → комплект документов электрохозяйства (приказы, перечни, инструкции, журналы) + самопроверка по опубликованным чек-листам Госэнергогазнадзора + календарь сроков и реестр удостоверений.
- **Кто платит:** организации с электроустановками (ответственные за электрохозяйство), компании на аутсорсинге электрохозяйства, ЭТЛ как допродажа.
- **Госпуть:** Госэнергогазнадзор подведомственен Минэнерго; самопроверка по его чек-листам работает на профилактику нарушений — отдельный повод для разговора с надзором.
- **MVP:** 3–4 недели. Ядро на Python + шаблоны DOCX + языковая модель для адаптации инструкций под объект.
- **Риски:** ответственность за корректность документов — нужен методолог-энергетик; права на тексты ТКП.

### 3. Прораб-бот
- **Что:** бригада шлёт в мессенджер голос, фото и объёмы → ИИ раскладывает по объектам и этапам → вечерняя сводка руководителю; простои с фото как основание для претензий.
- **Кто платит:** электромонтажные компании; позже — бригады РЭС.
- **MVP:** 2–4 недели. n8n + Telegram или Viber + распознавание речи + языковая модель + PostgreSQL или NocoDB.
- **Риски:** привычки полевых сотрудников; конкуренция с сервисами для стройки.

### 4. ИИ-ассистент по ТКП и тренажёр к проверке знаний
- **Что:** ответы по ТКП и правилам с цитатой пункта; адаптивные тесты к ежегодной проверке знаний с разбором ошибок.
- **Кто платит:** электротехнический персонал, организации, учебные центры; позже — облэнерго.
- **MVP:** 3–5 недель. RAG из AI Employee SaaS (pgvector).
- **Риски:** права на тексты ТКП (официальные тексты распространяются платно); ответственность за неверный ответ — только с цитатой и ссылкой на пункт.

### 5. Тендерный радар РБ
- **Что:** ежедневный сбор закупок с icetrade.by, goszakupki.by и БУТБ → ИИ-отбор под профиль компании → выжимка требований и стоп-факторов в мессенджер.
- **Кто платит:** электромонтажные, проектные и сервисные компании. Заодно инструмент для поиска собственных заказчиков.
- **MVP:** 2–3 недели. n8n + парсинг + языковая модель + бот.
- **Риски:** изменения и ограничения площадок; тендерные сервисы уже есть — отличаться выжимкой и отраслевым фильтром.

### 6. Спецификации и ВОР из PDF и сканов
- **Что:** проект в PDF или скане → таблица позиций с марками и количествами → проверка человеком → Excel для сметы, закупки или КП.
- **Кто платит:** сметчики и снабжение монтажных компаний, проектировщики, дистрибьюторы электротехники.
- **MVP:** 2–3 недели. Python + модель с распознаванием изображений + валидация; опыт обработки вложений из WAv02.
- **Риски:** плохие сканы; конфиденциальность проектов при облачной модели.

### 7. Цифровые обходы и дефекты
- **Что:** QR-паспорта оборудования, маршруты обходов, чек-листы с фото, журнал дефектов с ИИ-классификацией.
- **Кто платит:** службы главного энергетика, управляющие компании и ТЦ; позже — РЭС облэнерго (удобный вход в госсектор).
- **MVP:** 6–8 недель. PWA с офлайн-режимом + PostgreSQL + языковая модель.
- **Риски:** офлайн-режим; конкуренция с системами ТОиР.

### 8. Исполнительная документация
- **Что:** АОСР из журналов и отчётов, база сертификатов, входной контроль с распознаванием, пакет документов к допуску электроустановки.
- **Кто платит:** электромонтажные компании.
- **MVP:** 4–6 недель. Python + шаблоны.
- **Риски:** нужно подтвердить белорусские формы и требования к ИД; требования технадзора заказчика.

### 9. Приём заявок для электросервиса
- **Что:** WAv02, перенастроенный под электромонтаж, ЭТЛ и сервис электрохозяйства.
- **MVP:** 1–2 недели. n8n + Bitrix24 + языковая модель.
- **Риски:** не отраслевой продукт, много конкурентов. Роль — быстрые деньги и вход к клиентам для продуктов 1–3.

### 10. Электронный наряд-допуск
- **Что:** оформление нарядов по шаблонам, проверка групп и удостоверений членов бригады, ИИ-проверка мер безопасности.
- **Кто платит:** облэнерго, промышленные предприятия, наладочные организации.
- **MVP:** 2–3 месяца.
- **Риски:** юридическая значимость и электронная подпись, требования ОАЦ, безопасность людей. Флагман для разговора с Минэнерго, но не первый продукт.

## Выход на рынок РБ

- Минэнерго софт не покупает. Покупают предприятия: ГПО «Белэнерго» → шесть РУП-облэнерго → филиалы (электрические сети и РЭС, энергосбыт, станции), а также наладочные, ремонтные и проектные организации отрасли. Закупки идут через тендеры.
- Путь: 2–3 частных клиента → кейс с цифрами → бесплатный или символический пилот в одном филиале облэнерго через главного инженера или начальника профильной службы → отзыв → научно-технический совет Белэнерго → тиражирование и тендер.
- Министерство — на этапе тиражирования. Если там есть знакомые, просить помочь с пилотной площадкой, а не купить продукт.
- Госсектор РБ: защита информации по требованиям ОАЦ, закон о персональных данных, хостинг в РБ. OpenAI и Anthropic официально не обслуживают Беларусь, поэтому для госзаказчиков — локальная модель на их сервере. Частникам на старте подходит облако, но модель в архитектуре должна заменяться без переделки.
- Продукты 1, 2 и 4 переносятся в РФ заменой норм и шаблонов (ПТЭЭП, ПУЭ, Ростехнадзор).

## Инструменты: n8n или код

- n8n — для прототипов, интеграций и продуктов-«связок»: 3, 5, 9. Самый быстрый путь к демо; уже освоен в WAv02.
- Python — ядро для 1, 2, 4, 6, 7, 8, 10:
  - главная ценность — документы по строгим формам: шаблоны DOCX (docxtpl) и конвертация в PDF;
  - нормы, расчёты и проверки требуют тестов и версий;
  - кабинеты клиентов, роли и мультиарендность требуют своего бэкенда — стек уже есть в AI Employee SaaS (FastAPI, PostgreSQL, Next.js);
  - лицензия n8n разрешает внутреннее использование и внедрения у клиентов; если n8n становится частью тиражного продукта, может понадобиться коммерческая лицензия (Embed) — проверить до запуска.
- В каталоге многие из этих идей помечены как low-code: это про самый быстрый MVP. Для продукта на продажу ядро — код.
- Make и Zapier не подходят: иностранное облако, данные уходят за рубеж, оплата из РБ затруднена.
